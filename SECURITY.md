# Security

English | [简体中文](SECURITY.zh-CN.md)

Token Killer handles API keys and OAuth credentials. Never paste real credentials, authorization codes, request logs, or account details into a public issue.

If you discover a credential leak, leaderboard verification bypass, or another issue that could affect other users, use the repository's private **Report a vulnerability** form. Include only the minimum reproduction needed, and never upload a production secret that is still valid.

Regular bugs and interface problems can be reported through public issues.

## Browser credential boundary

API keys and OAuth credentials are encrypted at rest with a non-exportable AES-GCM key generated by the browser and stored in IndexedDB. This prevents casual plaintext inspection and accidental inclusion in exported settings. It is not protection against malicious JavaScript running in the same origin: an XSS vulnerability, a compromised browser extension, or a compromised deployment can still use credentials while the site is open. Use a dedicated origin, keep dependencies current, and deploy only reviewed builds.

The static frontend sends ordinary API requests directly from the browser. Subscription OAuth requires the optional authorization Worker for token exchange and upstream compatibility; credentials and prompts pass through that Worker in memory but are not written to the leaderboard database.

Token Killer does not automatically retry inference requests whose network outcome is unknown. A timeout, CORS failure, or interrupted connection may occur after the provider has accepted and billed the request, so the run stops and asks the user to inspect the provider's own usage records.

An optional mainland geo probe can issue a short-lived signed location assertion for regional leaderboards. The assertion contains only normalized country, province, city, timestamps, and a random nonce; it contains no installation ID, API credential, prompt, or model response. The probe necessarily receives the visitor's source IP at the network layer, so operators should disable access logging or apply an appropriate retention policy. Never enable `TRUST_GEO_HEADERS` unless a trusted reverse proxy strips client-supplied geo headers and injects its own values.
